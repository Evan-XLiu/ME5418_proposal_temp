% =========================================================
% Why
% =========================================================

\section*{Why:}

\begin{itemize}

    \item
    Pushing is a fundamental manipulation skill, useful when directly grasping an
    object is difficult or unnecessary, e.g., pre-positioning a component before
    grasping or assembly in industrial settings.

    \item
    Despite its simple appearance, pushing is contact-rich: the resulting object
    motion depends on contact location, pushing direction, object geometry, and
    friction, making a single hand-crafted controller hard to design for all
    configurations.

    \item
    In this project, we investigate whether reinforcement learning can learn a
    closed-loop Cartesian end-effector policy that uses a stick tool to move an
    object from a randomized initial pose to a desired target pose without
    relying on an accurate analytic model of the contact dynamics.

\end{itemize}


% =========================================================
% Conventional Algorithms
% =========================================================

\section*{Conventional Algorithms:}

\begin{itemize}

    \item
    Conventional pushing approaches rely on geometric planning, model-based
    control, or trajectory optimization (e.g., quasi-static limit-surface
    pushing models or model-predictive control), using an estimated object pose
    and contact dynamics to plan a sequence of actions toward the target.
    However, accurate contact dynamics are difficult to model when geometry and
    friction vary, so these methods often require precise physical parameters;
    small modeling errors also compound over a push sequence, forcing frequent,
    computationally expensive replanning to stay on target.

    \item
    Instead, we believe reinforcement learning is a good fit for this problem:
    rather than relying on an explicit (and potentially inaccurate) contact
    model, an RL agent can learn a closed-loop feedback policy directly from
    experience, implicitly capturing how contact location and pushing direction
    affect the resulting motion. We favor RL specifically over supervised or
    imitation learning because it requires no dataset of expert demonstrations:
    the agent can instead discover an effective strategy on its own by directly
    optimizing task success through trial-and-error interaction, a natural fit
    for this sequential, closed-loop decision-making problem.

\end{itemize}


% =========================================================
% Problem Statement
% =========================================================

\section*{Problem Statement:}

\begin{itemize}

    \item
    The core task is planar robotic pushing: a robot end-effector equipped with
    a vertical stick must push rigid objects with varied planar geometries into
    their corresponding target regions on a bounded tabletop. The simulation
    represents the stick's contact tip as a kinematic planar end-effector proxy
    while abstracting away the robot arm, joint kinematics, and joint-level
    control.

    \item
    This is a single-agent robotic manipulation task at the Cartesian
    end-effector level. At each control step, the policy receives the planar
    position of the end-effector proxy and the object pose; no force/torque or
    tactile sensing is assumed. It commands the next planar target point of the
    end-effector proxy, which is moved by the environment's built-in position
    controller. The study therefore evaluates contact-point selection and
    closed-loop end-effector control rather than joint-space motion planning.

    \item
    At the start of each episode, an object geometry is sampled from the
    training set, and the end-effector proxy position and object pose are
    randomized. The corresponding target pose remains fixed to keep the primary
    learning objective focused.

    \item
    The policy must place the current object into its target region within a
    limited number of control steps (e.g., 300 per episode). An episode succeeds
    when object--target coverage exceeds $95\%$.

    \item
    Required robustness tests use multiple training geometries, held-out object
    geometries, broader initial-pose ranges, and multiple simulator damping
    settings. Friction changes, randomized targets, and a full 7-DoF robot-arm
    model with a stick tool are further extensions because they require a
    higher-fidelity simulation.

\end{itemize}


% =========================================================
% RL Cast
% =========================================================

\section*{RL Cast:}

\begin{itemize}

    \item
    \textbf{State space:}
    We use the normalized structured state
    $s_t=[x_{ee,t},y_{ee,t},x_{o,t},y_{o,t},\theta_{o,t},g_o]$, containing the
    planar end-effector proxy position, object pose, and a compact geometry
    descriptor $g_o$ formed from normalized boundary keypoints. The matching
    target geometry and pose are known by the environment and are used to
    compute reward and evaluation metrics.

    \item
    \textbf{Action space:}
    The continuous action
    $a_t=[x^{\mathrm{cmd}}_{ee,t},y^{\mathrm{cmd}}_{ee,t}]\in[0,1]^2$
    specifies the next normalized Cartesian target of the end-effector proxy.
    An internal position controller moves the stick-tip proxy toward this point.
    A higher-fidelity robot implementation can map the same planar command to
    the physical end-effector after inverse kinematics and reachability checks.

    \item
    \textbf{Reward structure:}
    We use a dense pose-progress reward with normalized position and orientation
    terms, so their relative weights are not determined by the choice of units:

    \[
        r_t =
        w_p \frac{d_{\mathrm{pos},t}-d_{\mathrm{pos},t+1}}{L}
        +w_r \frac{d_{\mathrm{rot},t}-d_{\mathrm{rot},t+1}}{\pi}
        - c_{\mathrm{step}}
        + R_s\mathbf{1}[\mathrm{success}_{t+1}]
        - c_b\mathbf{1}[\mathrm{invalid}_t].
    \]

    Here $d_{\mathrm{pos}}=\|p-p^*\|_2$ is measured in normalized workspace
    units and $L=\sqrt{2}$ is the diagonal of the normalized workspace. The
    orientation error is the shortest angular distance,
    $d_{\mathrm{rot}}=|\operatorname{atan2}(\sin(\theta-\theta^*),
    \cos(\theta-\theta^*))|$, measured in radians. Pose errors are evaluated
    after each action; for symmetric objects, the equivalent target orientation
    that minimizes this error is used. $\mathbf{1}[\cdot]$ denotes an indicator
    function. Fixed initial settings are $w_p=w_r=1$,
    $c_{\mathrm{step}}=0.01$, $R_s=10$, and $c_b=1$. Reward tuning is limited
    to a small pilot study of the position-to-orientation weight ratio; the
    selected values are then held fixed across all methods, seeds, and test
    conditions.

    Success requires more than $95\%$ object--target coverage; the success bonus
    is awarded once and the episode then terminates. Episodes reaching the step
    limit are truncated without a success bonus. End-effector commands are
    clipped to the normalized workspace, with $c_b$ applied to invalid
    commands. We do not penalize loss of contact, since moving around the object
    and establishing a new contact may be necessary to correct orientation. The
    progress terms supplement the environment's coverage criterion with
    feedback before the object overlaps the target, while the per-step cost
    discourages unnecessary delays.

    \item
    \textbf{Neural Network Structure:}
    Since the structured observation remains modest-dimensional, we plan to use
    a simple MLP (e.g., two hidden layers of 256 units, ReLU) for the policy and
    value networks, following common continuous-control PPO defaults (e.g.,
    Stable-Baselines3), with the actor and critic sharing a trunk or fully
    separate if training is unstable.

\end{itemize}


% =========================================================
% RL Algorithms
% =========================================================

\section*{RL Algorithms and Envisioned Results:}

\begin{itemize}

    \item
    We use Proximal Policy Optimization (PPO) as the sole algorithm in the core
    experiment, given its stability and wide use in continuous robotic control.

    \item
    We will train at least three independent random seeds and report the mean and
    standard deviation of task success rate, final target coverage, final
    position error, final orientation error, and steps-to-target over 100
    held-out episodes per seed and test condition, both overall and per
    geometry.

    \item
    Required tests cover seen and held-out object geometries, broader held-out
    initial poses, and multiple simulator damping settings. These tests measure
    robustness without requiring a separate robot simulator.

    \item
    As a baseline, we will compare against a heuristic controller that first
    moves the end-effector proxy to a contact point behind the object (relative
    to the target direction) and then pushes it toward the target, re-planning
    as the object-to-target direction changes. We use this lightweight heuristic
    rather than a full model-based planner, since the latter would itself
    require an accurate contact/friction model -- exactly the dependency RL
    avoids. We expect the learned policy to perform better on cases requiring
    multiple contacts or simultaneous position/orientation adjustment.

\end{itemize}
