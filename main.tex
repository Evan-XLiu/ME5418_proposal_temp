% =========================================================
% Why
% =========================================================

\section*{Why:}

\begin{itemize}

    \item
    Pushing is a fundamental manipulation skill, useful when directly grasping an
    object is difficult or unnecessary, e.g., pre-positioning a component before
    grasping or assembly in industrial settings.

    \item
    Despite its simple appearance, pushing is contact-rich: the resulting object
    motion depends on contact location, pushing direction, object geometry, and
    friction, making a single hand-crafted controller hard to design for all
    configurations.

    \item
    In this project, we investigate whether reinforcement learning can learn a
    closed-loop pushing policy that moves an object from a randomized initial pose
    to a desired target pose without relying on an accurate analytic model of the
    contact dynamics.

\end{itemize}


% =========================================================
% Conventional Algorithms
% =========================================================

\section*{Conventional Algorithms:}

\begin{itemize}

    \item
    Conventional pushing approaches rely on geometric planning, model-based
    control, or trajectory optimization (e.g., quasi-static limit-surface
    pushing models or model-predictive control), using an estimated object pose
    and contact dynamics to plan a sequence of actions toward the target.
    However, accurate contact dynamics are difficult to model when geometry and
    friction vary, so these methods often require precise physical parameters;
    small modeling errors also compound over a push sequence, forcing frequent,
    computationally expensive replanning to stay on target.

    \item
    Instead, we believe reinforcement learning is a good fit for this problem:
    rather than relying on an explicit (and potentially inaccurate) contact
    model, an RL agent can learn a closed-loop feedback policy directly from
    experience, implicitly capturing how contact location and pushing direction
    affect the resulting motion. We favor RL specifically over supervised or
    imitation learning because it requires no dataset of expert demonstrations:
    the agent can instead discover an effective strategy on its own by directly
    optimizing task success through trial-and-error interaction, a natural fit
    for this sequential, closed-loop decision-making problem.

\end{itemize}


% =========================================================
% Problem Statement
% =========================================================

\section*{Problem Statement:}

\begin{itemize}

    \item
    We consider a tabletop planar pushing environment with a single robot
    end-effector (pusher), a movable rigid object, and a target pose, on a
    bounded square tabletop (roughly $0.4\,\mathrm{m} \times 0.4\,\mathrm{m}$).
    The core experiment uses two object geometries: a T-shaped object and a
    rectangle. This keeps the geometry variation small enough to be feasible
    while testing whether the policy relies on one specific contact shape.

    \item
    This is a single-agent, single-robot task with no inter-agent communication.
    At each control step, the agent is assumed to have full-state knowledge of
    the pusher position and the object's planar pose (position and orientation),
    provided directly by the simulator and analogous to an overhead-camera or
    motion-capture pose estimator in a real setup; no force/torque or tactile
    sensing is assumed. The agent's only capability is to command the planar
    position of the pusher (it cannot grasp or lift the object), so the object
    can only be moved indirectly through contact.

    \item
    At the start of each episode, the object's initial pose, target pose,
    geometry, and object--table friction coefficient are randomized. We use a
    uniform training range of $\mu\in[0.3,0.7]$ and reserve fixed values
    $\mu\in\{0.2,0.5,0.8\}$ for robustness testing.

    \item
    The robot must reach the target configuration within a limited number of
    control steps (e.g., 200--300 per episode), succeeding when the position
    error is below $2\,\mathrm{cm}$ and the orientation error is below
    $10^{\circ}$.

    \item
    Friction and geometry randomization are part of the required experiment,
    rather than optional extensions.

\end{itemize}


% =========================================================
% RL Cast
% =========================================================

\section*{RL Cast:}

\begin{itemize}

    \item
    \textbf{State space:}
    Low-dimensional robot and object states, including:

    \begin{itemize}
        \item current pusher/end-effector position;
        \item object position and orientation;
        \item target position and orientation;
        \item relative object-to-target position and orientation;
        \item optionally, object and robot velocities.
    \end{itemize}

    \item
    \textbf{Action space:}
    A continuous action space controlling the planar motion of the
    pusher/end-effector, $a_t = [\Delta x, \Delta y]$, the desired displacement
    per control step. If a robotic arm is used, these commands can instead be
    converted into end-effector Cartesian control commands.

    \item
    \textbf{Reward structure:}
    We use a dense pose-progress reward with normalized position and orientation
    terms, so their relative weights are not determined by the choice of units:

    \[
        r_t =
        w_p \frac{d_{\mathrm{pos},t}-d_{\mathrm{pos},t+1}}{L}
        +w_r \frac{d_{\mathrm{rot},t}-d_{\mathrm{rot},t+1}}{\pi}
        - c_{\mathrm{step}}
        + R_s\mathbf{1}[\mathrm{success}_{t+1}]
        - c_b\mathbf{1}[\mathrm{invalid}_t].
    \]

    Here $d_{\mathrm{pos}}=\|p-p^*\|_2$ is measured in meters and
    $L=0.4\sqrt{2}\,\mathrm{m}$ is the workspace diagonal. The orientation
    error is the shortest angular distance,
    $d_{\mathrm{rot}}=|\operatorname{atan2}(\sin(\theta-\theta^*),
    \cos(\theta-\theta^*))|$, measured in radians. Pose errors are evaluated
    after each action, and $\mathbf{1}[\cdot]$ denotes an indicator function.
    Fixed initial settings are $w_p=w_r=1$, $c_{\mathrm{step}}=0.01$,
    $R_s=10$, and $c_b=1$. Reward tuning is limited to a small pilot study of
    the position-to-orientation weight ratio; the selected values are then held
    fixed across all methods, seeds, and test conditions.

    Success requires both $d_{\mathrm{pos}}<0.02\,\mathrm{m}$ and
    $d_{\mathrm{rot}}<\pi/18$; the success bonus is awarded once and the
    episode then terminates. Episodes reaching the step limit are truncated
    without a success bonus. An action requesting a pusher position outside
    the admissible workspace is marked invalid and clipped to the boundary;
    this incurs $c_b$ but does not end the episode. Workspace boundaries
    confine the object. We do not penalize loss of contact, since moving away
    and establishing a new contact may be necessary to correct orientation.
    The progress terms provide immediate feedback for actions that reduce either
    error, while the per-step cost discourages unnecessary delays.

    \item
    \textbf{Neural Network Structure:}
    Since the observation space is low-dimensional, we plan to use a simple MLP
    (e.g., two hidden layers of 256 units, ReLU) for the policy and value
    networks, following common continuous-control PPO defaults (e.g.,
    Stable-Baselines3), with the actor and critic sharing a trunk or fully
    separate if training is unstable.

\end{itemize}


% =========================================================
% RL Algorithms
% =========================================================

\section*{RL Algorithms and Envisioned Results:}

\begin{itemize}

    \item
    We use Proximal Policy Optimization (PPO) as the sole algorithm in the core
    experiment, given its stability and wide use in continuous robotic control.

    \item
    We will train at least three independent random seeds and report the mean and
    standard deviation of task success rate, final position error, final
    orientation error, and steps-to-target over 100 held-out episodes per seed
    and test condition.

    \item
    Required tests cover both object geometries and multiple fixed friction
    coefficients, including one nominal and two held-out conditions, to measure
    robustness beyond randomized initial and target poses.

    \item
    As a baseline, we will compare against a heuristic controller that first
    moves the pusher to a contact point behind the object (relative to the
    target direction) and then pushes it toward the target, re-planning as the
    object-to-target direction changes. We use this lightweight heuristic rather
    than a full model-based planner, since the latter would itself require an
    accurate contact/friction model -- exactly the dependency RL avoids. We
    expect the learned policy to perform better on cases requiring multiple
    contacts or simultaneous position/orientation adjustment.

    \item
    The core deliverable is therefore PPO versus the heuristic baseline under
    pose, friction, and two-shape randomization, evaluated across multiple seeds.
    Only if time remains will we add SAC, extra unseen geometries, or a comparison
    with the original unnormalized pose-error reward.

\end{itemize}
